0.1この設計書について

  • 前提の規模：1ホストに 1〜2 ワールド、1ワールドあたり最大 5 人。1プロセス、SQLite のファイルは1つ
  • VISION との関係：VISION の章は「VISION 4章」、この設計書の章は「D1」「D5 5.3」のように書く。仕組みの考え方は VISION を正とし、ここでは繰り返さずに参照する
  • 案：案 の枠は、ユーザーの合意を待っている提案。番号（P-01〜P-51）で返事ができる。合意したものは枠を外し、VISION に反映が要るものは VISION も直す（0.5）
  • 範囲：コア（Vivace.Core）と、コアが外に求める口。Misskey のプラグインと CLI は、コアとの境目だけを書いた

0.2ファイル

D1 実行モデル

エンジン（唯一の書き手）、Apply の形、レーン、ホライズンと締め切り、適用前の検査、状態遷移、トランザクション、時計、起動と追いつき。

D2 イベントと語彙

イベントの種別と段、種別ごとの Apply、行動の効果、requires と制限、出来事の効果、投入できるイベント、origin。

D3 データ

定義の TOML（ワールド、ペルソナ、固定予定、行動、出来事）、ドメイン型、SQLite のスキーマ、JSON の版。

D4 コンポーネント

アセンブリ、ポート（IClock、IStorage、IChannel、ILlmClient など）、コアの中の部品、公開 API、プラグイン。

D5 決定と状態変数

Decider のスコアの式、Planner の検査と補正、状態変数の既定値、反射、出来事の抽選、乱数、最短経路、同行。

D6 LLM と記憶

呼び出しの一覧、文脈の組み立て、記憶の選び方、受信箱と投稿の手順、記憶の整理、汚染の防止、量の目安。

D7 運用とテスト

失敗したときの振る舞い、定義の検証、観測、テストの層、最小の CLI。

D8 技術スタック

確定（C#、SQLite）と、ライブラリの候補、使わないもの、LLM の PoC で確かめること。
