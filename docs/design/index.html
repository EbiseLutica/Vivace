0.1この設計書について

  • 前提の規模：1ホストに 1〜2 ワールド、1ワールドあたり最大 5 人。1プロセス、SQLite のファイルは1つ
  • VISION との関係：VISION の章は「VISION 4章」、この設計書の章は「D1」「D5 5.3」のように書く。仕組みの考え方は VISION を正とし、ここでは繰り返さずに参照する
  • 案：案 の枠は、ユーザーの合意を待っている提案。番号（P-01〜P-58）で返事ができる。合意したものは枠を外し、VISION に反映が要るものは VISION も直す（0.5）
  • 範囲：コア（Vivace.Core）と、コアが外に求めるインターフェース。Misskey のプラグインと CLI は、コアとの境目だけを書いた

0.5枠の外の判断

案の枠に入れずに、本文に直接書いた判断。案（0.4）が「ほかを左右するもの」「VISION にない概念」なのに対し、ここは「VISION の読み方」「仕組みの細部」「調整前提の数値」。数が多く、すべてを人が読んで確かめることはできないので、合意の印は付けず、各判断の出どころを記録する。困ったときに出どころを見て、決め直してよいものかを判断する。

  • ユーザーが確認：ユーザーが1件ずつ読んで合意した
  • 一括で合意：設計の段階で、ユーザーがまとめて合意した。1件ずつは読んでいない
  • エージェント（PR #N）：実装の PR の中でエージェントが決め、PR のマージで入った。ユーザーは1件ずつは読んでいない

エージェントの判断は、運転して困ったら、ユーザーに断らずに決め直してよい。決め直したら、行を書き換え、出どころをその PR にする。
